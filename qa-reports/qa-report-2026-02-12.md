## Wave 1: Dashboard & Project Management

### dashboard-projects-tester

#### Things That Work Well
- Status badges use correct semantic colors — "Finalized" green, "In Progress" blue, pill-shaped border-only design
- Project metadata well-structured — filename, badge, relative timestamp, revision/flag counts with dot separators
- Delete confirmation dialog is properly destructive — `alertdialog` role, names specific project, warns "cannot be undone", red Delete button
- Delete executes cleanly — project disappears, toast confirms, no console errors, server-side removal
- Delete buttons use hover-reveal pattern (opacity-0 → group-hover:opacity-100) keeping rows clean
- New Project dialog is well-designed — auto-save, "Don't show again" checkbox, preserves intake settings
- "Don't show again" localStorage persistence works correctly
- No JavaScript errors throughout all testing

#### Issues Found

| # | Severity | Finding | Screenshot |
|---|----------|---------|------------|
| 1 | **High** | **"+New" button does nothing on the review page** — Header on review page renders without `onNewProject` prop. The handler silently exits when undefined. The button is completely inert from the review context — no feedback, no navigation, no error. | `dashboard-tester-new-project-dialog.png` |
| 2 | **High** | **`resetSession()` clears the Recent Projects list** — When "+New" calls `resetSession()`, it wipes the store's `sessions` array, making sidebar show "No saved projects yet." Sessions only re-fetch on full page reload. Looks like data loss even though it's only client-side. | `dashboard-tester-no-projects-after-new.png` |
| 3 | **Medium** | **Status badges overflow Recent Projects panel at wide viewports** — At 1920px, badges extend 40-51px past the 280px panel card edge. Filename `truncate` + badge `shrink-0` causes overflow. Works at 1280px. | `dashboard-tester-badge-overflow-1920.png` |
| 4 | **Medium** | **New Project dialog unreachable from review page** — Dialog only rendered in dashboard page, not in review page. Combined with #1, entire "+New" feature non-functional from review context. | `dashboard-tester-review-page-loaded.png` |

#### Sarah's Verdict
> "The bones are solid — the delete flow is exactly how I'd expect it, and the status badges look professional. But the '+New' button doing nothing on the review page? That's embarrassing. Fix the '+New' wiring and stop clearing my project history, and this becomes a respectable dashboard."

## Wave 2: Flag System

### flag-system-tester

#### Things That Work Well
- Document loads reliably with full PSA content, formatting, and paragraph structure
- Flag creation flow is smooth — sidebar "Flag this clause" button opens FlagDialog, category selection and note entry work, flag appears immediately
- FlagDialog design is polished — Attorney/Client type toggle, category pill buttons with clear color coding (blue=Business Decision, orange=Risk Alert, purple=For Discussion, gray=FYI)
- Flag card navigation works perfectly — clicking a flag card scrolls document to correct paragraph, selects it, updates sidebar context
- Flag margin icons render via CSS pseudo-elements with color coding per category, right-side inset border, and hover tooltip
- Zero JavaScript console errors throughout entire test session
- Flag removal works and correctly cleans DOM state (flagged class, data-flag-category, title tooltip)
- Text selection floating Flag button does appear and clicking it correctly opens FlagDialog for the right paragraph
- FlagsTab shows well-organized content when paragraph is selected — current paragraph flags at top, expandable "All Flags" section below

### Top Issues Sarah Would Notice First

1. **#9 — Flag edit creates duplicate instead of updating** (High) — Pencil icon on flag cards always calls create(), never update. Editing a flag creates a new one instead of modifying it.
2. **#10 — Flag remove deletes ALL flags on a paragraph** (High) — Remove takes only paraId, nukes every flag on that paragraph instead of the specific one clicked.
3. **#8 — Flags tab inaccessible without paragraph selection** (High) — Sidebar gates ALL tab content behind paragraph selection, hiding the working "All Flags" view that exists in FlagsTab.
4. **#19 — Finalized banner doesn't appear on page load** (High) — Status never hydrated from backend on page load. Banner only shows after client-side export action. Page refresh loses it.
5. **#1 — "+New" button does nothing on review page** (High) — Header renders without onNewProject prop. Button is completely inert from review context.
6. **#2 — resetSession() clears Recent Projects list** (High) — New Project flow wipes the store's sessions array, making project list appear empty.
7. **#11 — Text selection visual lost before floating Flag button appears** (High) — DOM mutations collapse browser selection before the floating button can process it reliably.

### Things Sarah Would Appreciate Most

- Export workflow is polished — dropdown options, proper file naming, re-download buttons, "Session remains open" messaging
- Delete project flow is textbook — destructive confirmation, proper roles, clean removal, toast feedback
- Flag card navigation works perfectly — click card, document scrolls, paragraph selects, sidebar updates
- Author name localStorage persistence is seamless
- Long-content mailto: fallback is thoughtful and well-implemented
- Zero JavaScript console errors across all 4 test waves

### Overall Assessment

> "This tool has real promise — the core review-to-delivery workflow is architecturally sound, and the export pipeline genuinely works. I can flag items, finalize a redline, download Word documents, and generate a transmittal email. The polish in areas like the export dropdown, delete confirmation, and mailto: fallback shows the developers care about the details.
>
> But there are seven High-severity issues that would block me from using this daily. The flag system needs edit-vs-create and per-flag removal to be trustworthy. The finalized status needs to persist across page loads so I know what I've already shipped. And the '+New' button needs to work from the review page — that's where I am when I want to start a new project.
>
> Fix those seven issues and address the mid-word truncation in transmittal, and I'd recommend this to a colleague. As-is, it's an impressive prototype that needs one more round of bug fixes before I'd trust it with a real deal."
