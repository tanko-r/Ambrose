## Eliminated

- hypothesis: The store's selectParagraph action is broken or doesn't trigger scroll
  evidence: selectParagraph (store.ts:261) correctly sets selectedParaId, and document-viewer.tsx has a useEffect (lines 245-262) that scrolls selectedParaId into view. This chain works fine -- it's used by clicking paragraphs in the document itself.
  timestamp: 2026-02-10T12:00:30Z

- hypothesis: Paragraph IDs don't match between flags and DOM elements
  evidence: Both flags and DOM use data-para-id attributes generated by html_renderer.py. The handleClickSection function (flags-tab.tsx:138) queries [data-para-id="${flagParaId}"] which matches the backend-rendered attributes. ID format is consistent.
  timestamp: 2026-02-10T12:00:30Z

- hypothesis: handleClickSection function is broken
  evidence: The function itself (flags-tab.tsx:135-142) correctly calls selectParagraph() then scrollIntoView(). It would work if it were ever called from a full-card click. It IS wired up as onClickSection prop to FlagCard, but FlagCard only uses it on the section_ref Badge, not the card div.
  timestamp: 2026-02-10T12:00:45Z

## Evidence

- timestamp: 2026-02-10T12:00:15Z
  checked: FlagCard component (flags-tab.tsx lines 36-103)
  found: The outer card <div> at line 57 has NO onClick handler. The only clickable navigation element is the section_ref Badge at lines 61-67, which is conditional on flag.section_ref existing.
  implication: Clicking anywhere on the card body (note, excerpt, category badge, whitespace) does nothing. Only clicking the tiny section reference badge navigates.

- timestamp: 2026-02-10T12:00:20Z
  checked: FlagCard onClickSection usage (flags-tab.tsx line 64)
  found: onClickSection is only invoked inside the section_ref Badge's onClick: `onClick={() => onClickSection?.(flag.para_id)}`. The prop is optional (`onClickSection?: (paraId: string) => void`) and only used in this one place.
  implication: Navigation only works when (a) the flag has a section_ref AND (b) the user clicks that specific badge. Most users would click the card itself.

- timestamp: 2026-02-10T12:00:25Z
  checked: handleClickSection in FlagsTab (flags-tab.tsx lines 135-142)
  found: Function correctly calls selectParagraph(flagParaId) and then document.querySelector + scrollIntoView. This function IS passed to every FlagCard as onClickSection.
  implication: The navigation logic itself is correct. The problem is purely that it's not triggered from the card-level click.

- timestamp: 2026-02-10T12:00:30Z
  checked: Document viewer scroll effect (document-viewer.tsx lines 245-262)
  found: useEffect watches selectedParaId and scrolls the matching [data-para-id] element into view (smart scroll with middle-third check). This is a SECOND scroll mechanism that would also trigger if selectParagraph were called.
  implication: There are actually two scroll mechanisms that would both work. The store-based one (useEffect) provides a reliable fallback even if the direct DOM querySelector in handleClickSection fails.

- timestamp: 2026-02-10T12:00:35Z
  checked: Backend HTML rendering (html_renderer.py line 29)
  found: Paragraphs are rendered with `data-para-id="{para_id}"` attributes.
  implication: DOM elements are correctly tagged for querySelector matching.

## Resolution

root_cause: The FlagCard component's outer <div> (flags-tab.tsx line 57) has NO onClick handler. The onClickSection callback is only attached to the small section_ref Badge element (line 64), which is (a) conditionally rendered only when flag.section_ref exists, and (b) a tiny UI target that users would not intuitively click. Users naturally click the card body, which has no click handler.

fix: Add an onClick handler to the FlagCard outer <div> that calls onClickSection(flag.para_id). The cursor should also be set to pointer to indicate clickability.
