<task type="auto">
  <name>Task 2: Fix version endpoint to use environment variables</name>
  <files>app/api/routes.py</files>
  <action>
Replace the existing `get_version()` function in `app/api/routes.py` (around line 2057-2085). The current implementation uses `subprocess.check_output(['git', ...])` which fails in Docker containers where .git is excluded.

New implementation:
```python
@api_bp.route('/version', methods=['GET'])
def get_version():
    """Get version info from env vars (no .git in container).

    In production (Railway), set these service variables:
      GIT_BRANCH = ${{RAILWAY_GIT_BRANCH}}
      GIT_COMMIT = ${{RAILWAY_GIT_COMMIT_SHA}}

    In local dev, falls back to subprocess git if env vars not set.
    """
    import os
    branch = os.environ.get('GIT_BRANCH')
    commit = os.environ.get('GIT_COMMIT')

    if branch and commit:
        return jsonify({'branch': branch, 'commit': commit})

    # Fallback: try git subprocess for local development
    import subprocess
    try:
        branch = subprocess.check_output(
            ['git', 'rev-parse', '--abbrev-ref', 'HEAD'],
            cwd=Path(__file__).parent.parent.parent,
            stderr=subprocess.DEVNULL
        ).decode().strip()
        commit = subprocess.check_output(
            ['git', 'rev-parse', '--short', 'HEAD'],
            cwd=Path(__file__).parent.parent.parent,
            stderr=subprocess.DEVNULL
        ).decode().strip()
        return jsonify({'branch': branch, 'commit': commit})
    except Exception:
        return jsonify({'branch': 'unknown', 'commit': 'unknown'})
```

This approach:
- Uses GIT_BRANCH/GIT_COMMIT env vars when available (production)
- Falls back to git subprocess for local development (preserving existing behavior)
- Returns 'unknown' if neither works

Do NOT change any other part of routes.py. Only replace the get_version function body.
