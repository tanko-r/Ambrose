<task type="auto">
  <name>Task 1: Backend Dockerfile and .dockerignore</name>
  <files>Dockerfile.backend, .dockerignore, requirements.txt</files>
  <action>
1. Add `gunicorn>=21.2.0` to requirements.txt (it is not currently present; needed for production WSGI server). Add it after the flask-migrate line in the "Core dependencies" section.

2. Create `Dockerfile.backend` at the project root using a multi-stage build:

Stage 1 (builder): FROM python:3.12-slim AS builder
- WORKDIR /build
- Install build deps: `apt-get update && apt-get install -y --no-install-recommends gcc libpq-dev && rm -rf /var/lib/apt/lists/*`
- COPY requirements.txt and `pip install --no-cache-dir --prefix=/install -r requirements.txt`

Stage 2 (runtime): FROM python:3.12-slim AS runtime
- WORKDIR /app
- COPY --from=builder /install /usr/local
- COPY app/ ./app/
- COPY migrations/ ./migrations/
- COPY run.py .
- Set ENV: PYTHONDONTWRITEBYTECODE=1, PYTHONUNBUFFERED=1, PORT=5000
- EXPOSE 5000
- CMD: gunicorn with --workers=2 --threads=4 --worker-class=gthread --worker-tmp-dir=/dev/shm --bind=0.0.0.0:5000 --log-file=- --timeout=120 "app.server:create_app()"

CRITICAL: Use python:3.12-slim (NOT alpine). Alpine lacks glibc which psycopg2-binary and scikit-learn require.

<task type="auto">
  <name>Task 2: Frontend Dockerfile, .dockerignore, and next.config.ts</name>
  <files>Dockerfile.frontend, frontend/.dockerignore, frontend/next.config.ts</files>
  <action>
1. Update `frontend/next.config.ts`:
   - Add `output: 'standalone'` to the NextConfig object (enables .next/standalone for Docker)
   - Rename the env var from `NEXT_PUBLIC_BACKEND_URL` to `BACKEND_URL` (it is server-side only, used in rewrites which are build-time; no NEXT_PUBLIC_ prefix needed)
   - The rewrites() function should read: `const backendUrl = process.env.BACKEND_URL || 'http://localhost:5000';`
   - This preserves local dev behavior (falls back to localhost:5000)

2. Create `Dockerfile.frontend` at the project root with three-stage build:

Stage 1 (deps): FROM node:22-alpine AS deps
- WORKDIR /app
- COPY frontend/package.json frontend/package-lock.json ./
- RUN npm ci --frozen-lockfile

Stage 2 (builder): FROM node:22-alpine AS builder
- WORKDIR /app
- COPY --from=deps /app/node_modules ./node_modules
- COPY frontend/ .
- ARG BACKEND_URL=http://localhost:5000
- ENV BACKEND_URL=${BACKEND_URL}
- RUN npm run build

Stage 3 (runner): FROM node:22-alpine AS runner
- WORKDIR /app
- ENV NODE_ENV=production PORT=3000
- COPY --from=builder /app/.next/standalone ./
- COPY --from=builder /app/.next/static ./.next/static
- COPY --from=builder /app/public ./public (only if public/ directory exists; check first)
- EXPOSE 3000
- CMD ["node", "server.js"]

3. Create `frontend/.dockerignore`:
```
node_modules/
.next/
*.md
.env*
```
  </action>
  <verify>Run `docker build -f Dockerfile.frontend -t redlining-frontend .` and confirm it builds successfully. Verify the standalone output is present in the image by running `docker run --rm redlining-frontend ls -la /app/server.js`.</verify>

</task>

<task type="auto">
  <name>Task 3: docker-compose.yml for local integration testing</name>
  <files>docker-compose.yml</files>
  <action>
Create `docker-compose.yml` at the project root with three services:

1. **postgres** service:
   - image: postgres:16-alpine
   - environment: POSTGRES_DB=redlining, POSTGRES_USER=postgres, POSTGRES_PASSWORD=postgres
   - healthcheck: pg_isready -U postgres -d redlining -t 1 (interval 5s, timeout 3s, retries 10, start_period 10s)
   - volume: postgres_data:/var/lib/postgresql/data

2. **backend** service:
   - build: context=., dockerfile=Dockerfile.backend
   - ports: 5000:5000
   - environment: DATABASE_URL=postgresql://postgres:postgres@postgres:5432/redlining, DATA_DIR=/app/data, CORS_ORIGINS=http://localhost:3000, FLASK_APP=app.server:create_app
   - volumes: backend_data:/app/data
   - depends_on: postgres (condition: service_healthy)
   - command: `sh -c "flask db upgrade && gunicorn --workers=2 --threads=4 --worker-class=gthread --worker-tmp-dir=/dev/shm --bind=0.0.0.0:5000 --log-file=- --timeout=120 'app.server:create_app()'"`
   - healthcheck: curl -f http://localhost:5000/health (interval 10s, timeout 5s, retries 5, start_period 30s)
   - Add comment: "Set GEMINI_API_KEY, CLERK_FRONTEND_API_URL, CLERK_JWKS_URL via .env file or shell export"

3. **frontend** service:
   - build: context=., dockerfile=Dockerfile.frontend, args: BACKEND_URL=http://backend:5000
   - ports: 3000:3000
   - environment: NODE_ENV=production
   - depends_on: backend (condition: service_healthy)

Named volumes: postgres_data, backend_data

Use version: '3.8' for broad compatibility.

IMPORTANT: The backend command runs `flask db upgrade` before gunicorn. This is the docker-compose equivalent of Railway's preDeployCommand. FLASK_APP env var is set so Flask CLI can discover the app.
  </action>
  <verify>Run `docker compose config` to validate the compose file syntax. Verify all three services are defined and dependencies are correct.</verify>
  <done>docker-compose.yml defines postgres, backend, and frontend services with proper health checks, depends_on conditions, and named volumes. `docker compose config` passes without errors.</done>
</task>
