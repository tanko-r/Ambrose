<task type="auto">
  <name>Task 1: Install Railway CLI and create project with services</name>
  <files></files>
  <action>
1. Install the Railway CLI if not already installed:
   `npm install -g @railway/cli`

2. Authenticate with Railway:
   `railway login`
   (This opens a browser for OAuth — if it fails with an auth error, create a checkpoint for the user to authenticate manually.)

3. Create a new Railway project:
   `railway init`
   Name the project "ambrose-redlining" or similar.

4. Create the backend service linked to the current repo:
   `railway service create backend`
   Set the root directory to `/` and configure it to use `railway.toml` at the project root.

5. Add a PostgreSQL plugin to the project:
   `railway add --plugin postgresql`
   This auto-injects DATABASE_URL into the backend service's environment.

6. Create a persistent volume on the backend service mounted at `/app/data`:
   Use the Railway CLI or dashboard. If CLI supports it:
   `railway volume create --mount-path /app/data`
   If not available via CLI, document that the user must create the volume in the Railway dashboard.

7. Set backend service variables via CLI:
   ```
   railway variables set FLASK_APP=app.server:create_app
   railway variables set DATA_DIR=/app/data
   railway variables set GIT_BRANCH='${{RAILWAY_GIT_BRANCH}}'
   railway variables set GIT_COMMIT='${{RAILWAY_GIT_COMMIT_SHA}}'
   railway variables set CORS_ORIGINS=<frontend-public-domain>
   ```
   Note: GEMINI_API_KEY, CLERK_FRONTEND_API_URL, and CLERK_JWKS_URL must be set by the user (see user_setup). CORS_ORIGINS will be updated after the frontend domain is known.

8. Create the frontend service:
   `railway service create frontend`
   Set the root directory to `/frontend` or configure to use `frontend/railway.toml`.

9. Set frontend service variables:
   ```
   railway variables set BACKEND_URL=http://<backend-private-domain>:5000
   railway variables set NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY=<from-user>
   ```
   BACKEND_URL must use the backend service's Railway private domain. Get this from:
   `railway status` on the backend service, or from the Railway dashboard.

IMPORTANT: The backend service MUST be deployed first so its private domain is known. Then set BACKEND_URL on the frontend service before deploying frontend.

If any Railway CLI command is not available or fails, fall back to documenting the equivalent dashboard steps for the user.

  <done>Railway project exists with backend and frontend services, PostgreSQL plugin attached, persistent volume created on backend, and all required environment variables configured.</done>

<task type="auto">
  <name>Task 2: Trigger deployment and verify health</name>
  <files></files>
  <action>
1. Deploy the backend service first:
   `railway up` (from the project root, targeting the backend service)
   Or push to the connected GitHub repo to trigger automatic deployment.

2. Wait for backend deployment to complete. Monitor logs:
   `railway logs`
   Confirm:
   - Build completes successfully
   - `flask db upgrade` runs (pre-deploy command in dashboard)
   - Gunicorn starts and binds to the port
   - Health check at /health returns 200

3. Once backend is healthy, note its private domain for the frontend BACKEND_URL.
   Update CORS_ORIGINS to include the frontend's public domain (if not already set).

4. Deploy the frontend service:
   Ensure BACKEND_URL is set to the backend's private domain, then deploy.
   `railway up` (targeting the frontend service)

5. Wait for frontend deployment to complete. Monitor logs:
   `railway logs`
   Confirm:
   - Build completes (Next.js standalone build)
   - `node server.js` starts
   - Health check at / returns 200

6. Get the frontend's public URL:
   `railway domain` or check the Railway dashboard.

7. Verify end-to-end: curl the public frontend URL and confirm it returns HTML.
   curl the backend /health endpoint to confirm it returns 200.
   curl the backend /api/version endpoint to confirm it returns git info from env vars.
  </action>

3. `curl https://<backend-public-url>/api/version` returns JSON with branch and commit
4. Railway dashboard shows both services as "Active" with passing health checks
